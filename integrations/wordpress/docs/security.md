# Security and retention

Pilot implementation: mandatory Code/PKCE S256/state/nonce; pinned full issuer and same-origin discovery endpoints; signed RS256 ID/access tokens; client/audience/expiry/session binding; versioned identity/admission APIs; no role claims; no email merge. The maintained locked JWT library is namespace-isolated with its license/provenance and Composer audit.

Private flow/session payloads use authenticated Sodium encryption with WordPress salts. Rotating those salts ends recoverability of outstanding flow/session associations and invalidates ordinary WP sessions. State and browser binding expire after five minutes and are single-use. Local tokens retained for targeted session destruction are encrypted; access/refresh tokens are not persisted. SHA-256 indexed mapping keys also retain original values for collision comparison.

WordPress capabilities/nonces protect settings/link/logout actions. Callback authority is OIDC state/browser binding and token validation; backchannel authority is the validated signed event. Both are intentionally reachable without a WP nonce. Neither route trusts unauthenticated payload claims. Tokens/codes/cookies/secrets are excluded from plugin audit and normal UI. Redact `code`, `state`, ticket bodies, Authorization and Cookie at proxies/APM; WordPress cannot erase upstream request logs.

The enforced cookie boundary uses the official [send_auth_cookies hook](https://developer.wordpress.org/reference/hooks/send_auth_cookies/), including its zero-expiration/user cookie-clearing convention. Only narrowly scoped validated SSO and verified host recovery permit new cookie emission. Core/Woo anonymous registration and forged checkout signup are guarded independently. Application Password authentication remains an API policy; it does not become a competing web-session issuer. Arbitrary trusted PHP can replace pluggable functions/write headers and needs a concrete adapter/security review.

Exclude all `wp-login.php?action=al_*`, the exact REST backchannel route (including `?rest_route=` installations), account/link/logout/diagnostic pages and authenticated account state from Cloudflare, Nginx/Varnish, WP Rocket and any full-page cache. Do not rely solely on PHP no-store headers when an upstream cache answers first. Keep cache-control/referrer/noindex headers. Redis object cache must not become a cross-site mapping namespace; all tables/options/transients are site-prefixed. No browser token storage/service worker is added, and AccessLobby's PWA cache/lifecycle contract is preserved.

No Wordfence allowlist, firewall bypass, cache rule or proxy trust change is automatically installed. Qualify each actual site's security plugins and trusted HTTPS/IP topology. No auth middleware may strip callback parameters or block a genuine signed backchannel request. Limit request sizes and rate-limit unauthenticated routes at the trusted proxy without exposing private data in keys.

The fixture suite exercises signed-token negatives, targeted logout/replay/device isolation, concurrent JIT/link/state operations, registration-hook elevation, missing audit/revocation storage, partial database migration and prerequisite fault injection. Enforced activation/reactivation also invalidates this site's existing cookie sessions so rollback-created passwords cannot become a competing login path. The compatibility/evidence records identify exact passing revisions.

Remaining production gates include independent adversarial review, load testing, actual CDN/cache/security/theme behavior, receipt/revocation load behavior and the estate's real host-recovery/backup rehearsal. A fixture result does not establish those deployment properties.

Data retention: active/inactive identity maps retain local ownership/provenance; audit expires after 90 days while active cleanup runs; private flow/session rows expire and are cleaned hourly. Uninstall retains plugin tables deliberately for safe recovery. A permanently retired site needs a host-authorized export/retention review and private-state purge. Never delete WP users or commerce to purge the connector. No raw historical chat, credentials or realm exports belong in Git.

Opaque receipt capabilities remain server-side, encrypted with local WordPress salts; the API stores only hashes. They are session/client/expiry-bound and travel solely in Authorization headers. Redact these headers at every proxy/APM. Status replies contain no subject/person/sid. Checks are bounded to 3 seconds, throttled, and fail authenticated access closed after the documented grace. An older API or pre-upgrade session does not receive the new guarantee.
