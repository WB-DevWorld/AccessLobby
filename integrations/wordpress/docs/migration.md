# Controlled account migration

1. Back up the database/files and restore into an isolated clone. Record the backup identifier and a tested rollback procedure. Inventory users by role/capabilities, customer/dormant/unlinked accounts and technical integrations. Check the actual custom privileged roles too; the UI's administrator/editor/shop-manager count is a minimum inventory, not a universal privilege classifier.
2. Install in hybrid mode. Test a controlled administrator and customer. Existing users sign in locally and explicitly Connect AccessLobby. Verify original WP ID, roles, authorship, order customer IDs, addresses, subscriptions/downloads and local B2B/member entitlements. A matching email cannot replace this proof.
3. Keep local login during the bounded migration period. Communicate a path for dormant/unlinked users; staff are linked explicitly. Do not reset/copy/synchronize password hashes. Configure and rehearse host emergency recovery and plugin deactivation/rollback.
4. The enforcing administrator must already have an active link. Run a fresh connection metadata check (ten-minute gate), record backup/rollback and recovery rehearsal references, inspect total/linked/unlinked privileged counts, and explicitly acknowledge remaining unlinked users/privileged accounts and session invalidation.
5. Enable AccessLobby only. Existing WP sessions are intentionally destroyed; users must re-enter through AccessLobby. Recheck wp-login, wp-admin, frontend forms, My Account, modal/mobile account UX, original destinations, outages, machine integrations and guest purchasing. The plugin never exposes local password login during an AccessLobby outage.
6. Roll back if the acceptance fails. Local passwords remain in WordPress, and host-authorized deactivation restores local login. Keep mapping data and evidence for diagnosis. No user/order record is deleted by rollback.

Do not enable enforced mode across an established production storefront without its own controlled cohort, backup/restore and approved promotion. Site mode does not change WordPress role ownership. Unlinked privileged acknowledgements are consequential and auditable; a reference is not a substitute for a recovery rehearsal.
