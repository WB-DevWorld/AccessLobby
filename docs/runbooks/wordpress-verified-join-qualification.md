## Read-only metadata helper

Use the qualified infra/scripts/iam-email-diagnostics.mjs from an existing protected operator process with Node24 and access to the private IAM backend. It accepts only http://iam:8080 or loopback:8080 and synthetic al-qual-* usernames. No public admin URL, redirect, credential URL, arbitrary account search or token argument is permitted. Three GETs read realm metadata, the VERIFY_EMAIL provider, and one exact synthetic-user query. Output is fixed boolean/status metadata: SMTP field presence, verification policy/action/account flags and access-token lifetime. SMTP host/from/user/password values, user IDs/emails, token values, raw responses and errors are not printed.

Supply a short-lived token from the existing approved private operator session through stdin. Keep it out of argv, public-service environment, shell tracing and logs. The existing API/backend execution environment can reach IAM privately; an owned temporary copy of this one script can run there without rebuilding images or exposing ports. Use the established protected operator procedure to select the actual container/path and clean up that copy. Do not copy an operator credential into plugin settings or a deployed public API environment.

Example shape, in an already prepared private backend execution environment:

~~~sh
node iam-email-diagnostics.mjs --base http://iam:8080 --username al-qual-join-test < "$IAM_EMAIL_OPERATOR_TOKEN_FILE"
~~~

Substitute the actual existing lower-case synthetic username and protected operator token source. The example account label must not be created merely to run the helper. The token file, if used, is privately generated by the approved operator route and remains outside Git with restrictive permissions. A private pipe is also supported. Exit0 means metadata checks pass, exit1 means verification/configuration prerequisites are incomplete, and exit2 means invalid input or unreadable metadata. Even exit0 does not establish mail delivery or a fresh verified OIDC claim.

The helper sends no mail and performs no configuration, user, role, token-lifetime or verified-state mutation.
