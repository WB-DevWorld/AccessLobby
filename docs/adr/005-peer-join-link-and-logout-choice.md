# ADR 005 — Peer join, legacy link and sign-out scope

**SOURCE-CONFIRMED:** AccessLobby supplies shared sign-in and a durable person identity; peer apps retain their own users, history and resource permissions. New users may begin in a peer app. Existing accounts must be explicitly linked; email does not establish account ownership. The owner has now chosen a sign-out prompt in every connected app: current app or all connected apps in the current browser session. All devices is a separate operation.

**MVP-PROVISIONAL implementation:** New peer users start authorization code + PKCE with `prompt=create` and complete verified registration before the peer creates a local account. Existing users prove control of their old peer session and the AccessLobby OIDC session within one short linking flow; the peer stores a unique, auditable `(issuer, sub, person.id, local user ID)` mapping. Conflicts stop for review. Peers preserve old login during migration. Current-app sign-out clears only that app session. All-apps sign-out clears the initiating session, requests RP-initiated issuer logout, and participating clients consume verified OIDC backchannel logout tokens scoped by `sid`. The first-party API persists revoked `sid` values for longer than its maximum web cookie life.

**Rollout and limits:** The example peer keeps sessions and links only in memory; actual peers must persist them and implement their own authenticated legacy-account proof. Registration and recovery require a working SMTP setup and explicit updates to an existing realm. Backchannel delivery to an offline peer is not guaranteed; peers must bound session life and choose a reconciliation/check strategy. This branch does not claim that POII, DonLoft, POS or other peers have integrated or that staging has exercised the new flows. Do not expose these controls as complete across the ecosystem until each peer passes the two-app join/link/SSO/local/global logout matrix.
