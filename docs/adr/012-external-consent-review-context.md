# ADR012 — Reviewed external consent context and inactive product preview

Status: **NEW-RECOMMENDATION / MVP-PROVISIONAL**, 2026-11-24. Reversible inactive preview; not owner approval of external activation or a legal retention policy. Relates to #59.

The alpha.4 preview recorded scope/policy without a product review screen or a binding to the reviewed registration. Alpha.5 adds a default-off first-party-web-only review/withdrawal UI and an application-specific configuration fingerprint. This extends ADR011; the first-party-only activation constraint and all existing token-admission gates remain closed to external clients.

Migration008 adds nullable fingerprints and consent display snapshots. It deliberately does not bless existing preview records. The fingerprint covers application UUID, unique client ID, display name, publisher Person, platform, exact callback/logout/backchannel URLs, admission, visibility and the minimal `openid` policy. A database trigger invalidates the profile review and withdraws existing grants when a covered registration changes. Restoring earlier URLs does not restore review or consent. These hashes are review context, not OIDC identity or a globally reusable publisher identifier.

`prepare-external-app APP --prepare REVIEW` still requires a previously verified domain and fresh DNS proof. `--reverify REVIEW` rechecks an existing requested/prepared external profile and withdraws previous consents. `--resume-preview REVIEW` applies only to a suspended preview, requires fresh proof/review, leaves it requested/inactive, and never restores old consent. Neither command provisions IAM or accepts IAM administration credentials. `--suspend REVIEW` blocks the profile and invalidates its consent. Audit events retain the affected actor/application; responses and UI omit internal person/provider subjects and opaque app identity values.

The preview API is versioned `accesslobby.external-preview.v0.2`. GET `/v1/preview/external-profiles/:applicationId` returns only current reviewed site metadata and its fingerprint. POST `/v1/preview/external-consents/:applicationId` requires exact policyVersion, scopes `["openid"]` and the fingerprint actually reviewed. A stale form fails409; unsupported scope/context fails400. GET `/v1/preview/external-consents` lists only the authenticated human's approvals using the original approved name/origin, including unavailable or changed sites. DELETE on that consent remains possible after publisher suspension/configuration changes, is idempotent, and cannot select another human. The first-party API derives the actor from a verified bearer; an app ID in a route never grants another app's authority.

Concurrent repeated approval creates one app identity and one audit/revision change. Withdrawal/re-consent retains the app's opaque identity referencing the same existing canonical Person. It never creates another Person from a pairwise subject. Application review, user consent, broad app entry and local WordPress roles/commerce remain separate.

The product routes `/connections` and `/connections/:applicationId` provide clear inactive-preview wording, minimal data categories, explicit approval/cancel and withdrawal. They work as native forms without JavaScript and require the normal same-origin POST boundary. A narrowly allowlisted returnTo (`/connections` or one exact UUID review path) is sealed with the OIDC flow and revalidated after complete person/context resolution. Ordinary sign-in routing remains unchanged when no reviewed continuation is present or the feature is off. No query, foreign origin, action route or arbitrary return URL is accepted. This continuation does not grant consent automatically.

Both API and web require exact `EXTERNAL_PROFILE_PREVIEW_ENABLED=true`; Compose defaults false. Disabled API/UI/action routes return404. These private routes send no-store, are not worker-cached, and cannot initiate a service-worker update. The worker still caches only the neutral shell and immutable build assets.

**Implemented scope:** context-bound inactive consent, display/withdrawal, private review lifecycle and app identity continuity. **DEFERRED:** privacy-safe external ID/access/userinfo/session issuance and external API audience, automatic verified client provisioning, approved sensitive scopes/retention/erasure, external account-linking contract, operator self-service onboarding and external-like WordPress pilot. A prepared profile or an approved preview screen is not a usable external OIDC client.

Validation: PostgreSQL integration covers transfer/domain/route/name changes, restoration, legacy null contexts, live proof requirement, concurrent idempotence, suspension/review/re-consent and one canonical Person. CI adds production Next.js + real Keycloak/API/PostgreSQL browser coverage, disabled routes, mobile/no-JavaScript OIDC continuation and approval/withdrawal, stale form, cross-origin and other-user denial. Exact passing source/results belong in the release evidence, not inferred from this ADR.

Sources checked: [OIDC consent](https://openid.net/specs/openid-connect-core-1_0.html#Consent), [OIDC pairwise subject identifiers](https://openid.net/specs/openid-connect-core-1_0.html#SubjectIDTypes), current local application/identity/preview implementation and migration invariants. OIDC consent is a protocol authorization concept; this preview does not settle legal data-processing requirements.
